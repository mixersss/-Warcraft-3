# Пиратия: автоматическое создание ботов — Alpha 04

Исправлены номера внешности при создании персонажа: причёска **2000**, лицо **2554**,
по таблицам меню создания именно предоставленного клиента. В Alpha 03 были ошибочно
подставлены номера деталей модели; сервер отклонял создание с кодом **520**.
Существующие аккаунты ботов используются повторно, создавать их заново не нужно.

Исправлена ошибка **`Stage=save_bot_identities ArgumentException`** из Alpha 02.
Причина: PowerShell превращал `$null` в пустое имя резервного файла для `File.Replace`.
Теперь при сохранении используется явное имя, а предыдущие данные сохраняются в резервной копии.

**Если обновляешь Alpha 02/03:** распакуй новый архив, скопируй папку **`data`** из старой
папки программы в новую и запусти `Start-Bot.cmd` из новой папки. Файлы внутри `data`
редактировать или удалять не нужно. Используй тот же Windows-ПК и пользователя.

Программа сама создаёт **три отдельных игровых аккаунта**, придумывает им логины,
пароли и имена персонажей, создаёт персонажей в Аргенте и подключает их **без окон игры**.
Вручную регистрировать аккаунты, создавать персонажей и вводить их пароли не нужно.

Пока это проверка создания и входа: после подключения персонажи стоят 60 секунд
и выходят. **Передвижение, бой, подбор добычи и прокачка ещё не реализованы.**

## Что сделать

1. Распакуй **весь ZIP** в новую отдельную папку, например `C:\PiratiaBots04`.
   Внутри должны быть `Start-Bot.cmd` и папка `src`. В серверные папки ничего копировать не нужно.
2. Запусти свой сервер обычным способом — включая карту `garner` (Аргент).
3. Дважды нажми **`Start-Bot.cmd`** на том же Windows-ПК, где установлен сервер.
4. Если программа сообщает, что Python не найден, установи **Python 3.12 для Windows**
   с https://www.python.org/downloads/windows/ . Отметь **Add python.exe to PATH**,
   затем снова открой `Start-Bot.cmd`.
5. Подожди. Программа проверит локальный SQL Server, создаст аккаунты,
   затем персонажей и выведет для каждого: **«вошёл в мир без окна игры»**.

Персонажей с именами `Bot…` можно найти своим основным аккаунтом в Аргенте.
Ботам не нужен запущенный `Game.exe`; открыто только одно общее окно программы.
Для остановки до окончания 60 секунд нажми **Ctrl+C** в этом окне.

## Повторный запуск

Просто снова открой `Start-Bot.cmd`. Программа использует тех же ботов и уже созданных
персонажей. Не удаляй созданную папку **`data`**: в ней сохраняются их данные.
Пароли в этом файле защищены Windows DPAPI для текущего пользователя Windows.
Эту папку не отправляй в чат и не публикуй. После переноса на другой ПК её пароли
автоматически не расшифруются — это отдельный шаг переноса, если он понадобится.

Если запустить программу повторно, пока она уже работает, второй запуск остановится.
Не копируй её в другую папку для каждого запуска: у каждой отдельной папки получится
свой набор ботов. Для обновления сохраняй свою папку `data`.

Для первого теста выбраны три обычных персонажа типа Ланс с начальной внешностью.
Все игровые характеристики и стартовое снаряжение назначает сам сервер при создании.
GM-права ботам не выдаются. Разные классы и поведение добавляются на следующих этапах.

## Если появилась ошибка

Пришли **`bot-report.json`**, файлы **`bot-report-01.json`**, `02`, `03`, если они есть,
и текст ошибки из окна. Они содержат только этапы, номера/размеры пакетов и коды отказов;
пароли и содержимое пакетов туда не записываются. Папку `data` присылать не нужно.

SQL-подготовка использует твой Windows-вход в **`localhost\SQLEXPRESS`**, базу
**`AccountServer`**, таблицу **`dbo.account_login`** — как при подключении через SSMS.
Пароли SQL `PiratiaAccount` / `PiratiaGame` вводить не требуется. Если у Windows-входа
нет прав на эту таблицу или схема отличается, программа остановится и выведет этап.
Не меняй настройки рабочего сервера заранее.

## Проверки и ограничения

18 автоматических тестов проверяют протокол входа, создание персонажа, повторное
использование персонажей, отказ сервера, шифрование, ping и выход. Блок внешности
персонажа сопоставлен с выполнением функции создания из предоставленного `Game.exe`
в эмуляторе x86. Алгоритмы шифрования сверены с предоставленным `GateServer.exe`.
Отдельный тест в PowerShell 7.4.6 воспроизвёл исходный `ArgumentException` и подтвердил
три последовательных сохранения, сохранность резервных копий и повторный запуск
с существующими данными после исправления. Windows PowerShell 5.1 здесь не запускался.

SQL-подготовка аккаунтов и вход подтверждены твоим запуском Alpha 03.
**Создание с исправленной внешностью и вход в настоящий игровой мир ещё требуют
проверки у тебя.** Тестовый обмен с макетом сервера не заменяет проверку на твоей сборке.
Это ещё не готовый боевой ИИ.

Программа добавляет только аккаунты с автоматически созданными именами `PB…`.
Существующие чужие аккаунты, пароли и персонажи не перезаписывает. При совпадении имени
с другим паролем останавливается. Серверные EXE/DLL/CFG не меняет. Создание персонажа
проходит через штатный сетевой запрос игры, а не ручное заполнение таблиц персонажей.

Работает только с `127.0.0.1:1973`; Python 3.9+ и стандартный Windows PowerShell 5.1.
Внешние Python-пакеты не нужны. Разработчику: `python -m unittest discover -s tests -v`.
Необязательные параметры: `python src/auto_bots.py --count 1 --seconds 60` (до 10 ботов).
Тест сохранения: `powershell -NoProfile -File tests/test_state_store.ps1`.
