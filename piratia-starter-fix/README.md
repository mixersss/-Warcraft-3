# Восстановление стартового задания и сундука — Fix01

В базе владельца у персонажей записаны русские города «Аргент»/«Шайтан».
Присланный CharBornScript.lua проверяет только Argent City/Shaitan City/Icicle Castle.
Обработчик выбирает Welcome, в котором штатно выдаётся сундук436. Это выявленное
несоответствие; фактический результат исправления в Windows GameServer ещё не проверен.

## Установка

1. Останови ботов. Штатно останови серверы: в служебном окне каждого GameServer
   выполни Stop(10) и дождись закрытия. Остальные службы останови прежним порядком.
   Не удаляй базы, персонажей или папку data.
2. Распакуй этот комплект в отдельную папку. Запусти Apply-Starter-Fix.cmd.
3. Вставь полный путь к своей папке resource и нажми Enter, например
   C:\PKO138 + Tools\resource. Можно указать непосредственно resource\script.
4. Должно появиться ГОТОВО. Установщик меняет только MisScript\CharBornScript.lua
   и calculate\functions.lua. До записи проверяет SHA256 именно присланных владельцем
   версий и создаёт рядом побайтовые резервные копии *.before-starter-fix-ДАТА.
   Если версия отличается или GameServer ещё работает, он остановится без замены.
5. Запусти сервер обычным Start-All.bat. Зайди новым героем, открой инвентарь и
   журнал заданий. Проверь Welcome и сундук436. Для уже созданного пострадавшего
   новичка подожди около30 секунд работы сервера, затем проверь Сенну и инвентарь.
6. После проверки запусти прежних ботов с их прежней data. Новые аккаунты не нужны.

## Что меняется

Обработчик рождения принимает шесть названий: три английских и Аргент/Шайтан/Ледынь.
В существующий cha_timer добавляется проверка восстановления раз в30 тиков времени
серверного таймера. Она использует штатный ObligeAcceptMission, не SQL-выдачу вещей.

Восстанавливаются только реальные игроки без профессии, у которых нет ни одной
начатой/завершённой Welcome1/2/3 или первоначальной заявки на класс58..61, есть
свободная клетка и нет сундуков436/985/986/987/988 в сумке, банке или экипировке.
Герои с уже пройденным стартом, начатой заявкой на класс или полученной профессией
сохраняются без дополнительной выдачи. Если старый герой уже использовал сундук,
этот комплект не выдаёт второй. Одна только смена birth через SQL не возвращает
пропущенное действие рождения; комплект базу данных не изменяет.

## Проверено

40 Lua-проверок с подменой native API: шесть названий, новые/пострадавшие герои,
повторный вызов без дублирования, история квестов, начатый класс, банк, полная сумка,
неигровой объект, отказ принятия. Оба изменённых файла прошли разбор Lua.
Установка на копии присланных файлов проверена; повторная установка ничего не меняет,
а изменение файлов пользователем блокирует перезапись. Проверки не заменяют живой
Windows-сервер. Скрипты владельца и любые пароли в комплект не включены.

## Откат

Снова штатно останови GameServer. Верни две соответствующие резервные копии
*.before-starter-fix-ДАТА на места CharBornScript.lua и functions.lua. Удали только
созданный установщиком resource\script\starter-birth-fix-01.sha256. Запусти сервер.
Откат файлов не отменяет уже принятого штатного задания или полученного сундука.
